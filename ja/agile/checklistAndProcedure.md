# Scrumban ミーティング・イベント一覧と進行方法の詳細ガイド

## 1. **デイリースタンドアップミーティング (Daily Stand-up)**

- **目的**: チームメンバーが現在の作業状況を共有し、障害要素を特定して、当日の目標を明確にするため。
- **進行方法**:

  - 毎日決まった時間（通常は午前中）に15分以内で実施します。
  - チームメンバー全員が立った状態で進行し、会議時間を短く保ちます。
  - 各メンバーが次の3つの質問について簡潔に共有します：

    - 昨日何を実施したか？
    - 今日何を実施する予定か？
    - 現在の作業に障害要素はあるか？

  - カンバンボードの前で実施し、作業の進行状況を視覚的に確認します。

## 2. **バックログリファインメント (Backlog Refinement)**

- **目的**: バックログアイテムを継続的にレビューし、優先順位の調整と作業単位への分解を行うプロセス。
- **進行方法**:

  - 定期的に（例：週1\~2回）実施します。
  - PO（Product Owner）または関係担当者が参加し、ストーリーの優先順位を調整します。
  - チームとともにアイテムを分析し、必要に応じて業務をさらに小さな単位へ分割します。
  - 作業に対する理解度と準備状態を高め、後続作業に支障が出ないように備えます。

## 3. **リリースプランニング (Release Planning)**

- **目的**: 中長期の目標設定と機能リリース計画の策定。
- **進行方法**:

  - 必要時または定期的に（例：毎月、四半期ごと）実施します。
  - チーム全体が参加し、目標機能とリリーススケジュールを協議します。
  - カンバンボードとスクラムのスプリント概念を適切に組み合わせて計画を立てます。
  - 作業量（Work In Progress、WIP）制限を考慮し、現実的なスケジュールを策定します。

## 4. **レビューミーティング (Review Meeting)**

- **目的**: 完了した作業の成果物を共有し、フィードバックを得る場。
- **進行方法**:

  - 定期的または必要に応じて実施します。
  - チームメンバーが完了した作業をデモンストレーション、または結果を共有します。
  - ステークホルダーおよびPOが出席し、フィードバックを提供します。
  - 改善点と成功事例をチーム全体で議論します。

## 5. **レトロスペクティブミーティング (Retrospective)**

- **目的**: チームの作業プロセスとコラボレーション手法を振り返り、改善点を導出するため。
- **進行方法**:

  - 定期的に実施します（例：2週間に1回、または月1回）。
  - チームメンバー全員が参加します。
  - 一般的な進行手順：

    - 良かった点の共有
    - 問題点と障害要素の洗い出し
    - 改善アイデアの議論
    - 実行可能なアクションアイテムの選定

  - 選定されたアクションアイテムは次回以降の期間に反映して実行します。

## 6. **優先順位調整およびWIP制限管理ミーティング**

- **目的**: カンバンの要であるWIP制限を点検し、優先順位を調整して作業フローを最適化するため。
- **進行方法**:

  - 必要に応じて随時実施可能です。
  - チームが現在WIP上限を超過していないか確認します。
  - ボトルネックや遅延状況を把握し、解決策を協議します。
  - 新規作業の追加時に優先順位を再調整します。

# 追加参考

- **カンバンボードの活用**: すべてのミーティングはカンバンボード（物理ボードまたはデジタルボード）を中心に行い、作業の可視化を徹底します。
- **柔軟な進行**: Scrumbanには厳格なスプリント期間がなく、必要に応じてミーティングの頻度や内容を調整できます。
- **WIP制限の重要性**: WIP制限を適切に守ることが、作業効率の向上とボトルネックの最小化において重要です。

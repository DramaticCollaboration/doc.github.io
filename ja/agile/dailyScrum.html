デイリースクラムの進め方 ​

  1. 時間と場所の固定
  • 毎日同じ時間（例：午前9時）に実施します。
  • 同じ場所（会議室またはオンラインビデオ会議）に集まります。
  1. 参加者
  • 開発チーム全員（開発者、QA など）
  • スクラムマスター（進行補助）、プロダクトオーナー（PO）はオブザーバーとして参加可能です。
  1. 進行方式

  • 所要時間は 15分以内 に収めます。

  • チームメンバーが 順番に共有 します。

  • 3つの質問 に沿って簡潔に報告します。

    1. 昨日何を行いましたか？
    2. 今日何を行う予定ですか？
    3. 進行を妨げている障害（ブロッカー）はありますか？
  1. 重要原則
  • 詳細な技術説明ではなく「共有」を中心に行います。
  • 障害の具体的な解決策は、スクラム終了後に別途議論します。
  • 進捗報告ではなく、チーム間の同期（シンク）を目的 とします。

デイリースクラム 進行例スクリプト ​

基本情報 ​

  • 時間: 毎日 10:00（15分以内）
  • 参加者: 開発チーム全体、スクラムマスター、必要に応じてプロダクトオーナー（PO）
  • 形式: スタンドアップ形式（リモートの場合はビデオ会議）

1. 開始の挨拶および会議目的の確認（2分） ​

スクラムマスター:

「おはようございます。デイリースクラムを開始します。本日も各自、昨日実施したこと、今日予定していること、そして障害となる要素があれば共有をお願いします。」

2. メンバーごとの進捗共有（10分） ​

佐藤（開発） ​

「昨日はユーザーログイン API の開発を完了しました。本日はユーザープロフィール取得機能を実装する予定です。現在、特に障害となる要素はありません。」

鈴木（デザイン） ​

「昨日は決済ページの UI デザインを完了し、開発チームへ引き渡しました。本日は管理画面のデザインに着手する予定です。ただし、開発パートと認識を合わせたい点があるため、午後に短いミーティングをお願いできますでしょうか？」

スクラムマスター:

「承知しました。会議後に関係メンバー間で日程を調整します。」

高橋（バックエンド） ​

「昨日は DB 最適化作業を進め、本日はパフォーマンステストを実施する予定です。ただし、テストサーバーの CPU 使用率が高いため、モニタリングが必要になりそうです。」

スクラムマスター:

「障害要素として記録しておき、会議後にインフラチームと協議します。」

田中（QA） ​

「昨日はログイン機能のテストを完了し、本日は新たに追加された決済機能のテストを開始する予定です。テストシナリオのうち、開発チームに確認したい箇所がいくつかあります。」

スクラムマスター:

「会議後、すぐに担当の開発者とお繋ぎします。」

3. 障害要素の要約および対応計画の策定（2分） ​

スクラムマスター:

「ここまで共有された障害要素を整理すると、以下の3点になります。

  1. デザイン・開発間の調整ミーティングが必要
  2. テストサーバーの CPU 使用率に関する問題
  3. QA テストシナリオの確認が必要

これら3つの項目については、私から各担当者と調整を進めます。」

4. 会議の終了（1分） ​

スクラムマスター:

「皆さん、今日やるべきことが明確になり、障害要素も把握できました。本日の会議はここで終了し、個別の相談が必要な方はこのまま議論を続けてください。本日もよろしくお願いします。」

デイリースクラムを効果的に運用するヒント ​

  • 時間厳守: 15分ルールを守るため、立ったまま会議を行うことを推奨します。
  • 問題解決会議の禁止: 深い議論は別途時間を確保して実施します。
  • 全メンバーの参加: 全員が偏りなく発言できる雰囲気をつくります。
  • 視覚的補助ツールの活用: カンバンボードやタスク管理ツールなどを併用します。
  • 障害要素への集中: 問題解決に向けたアクションプランを必ず策定します。

記録例 ​

担当者昨日やったこと今日やること障害要素
佐藤（開発）ログイン API 開発完了プロフィール取得機能の実装なし

デイリースクラム進行用チェックリスト ​

ファシリテーター（スクラムマスター）チェックリスト ​

  • [ ] 毎日同じ時間・場所（またはオンライン）で開始できたか？
  • [ ] 15分以内に終える準備ができているか？
  • [ ] 各メンバーが 昨日・今日・障害 の3項目のみを共有するよう促したか？
  • [ ] 共有された 障害（Blocking Issue） を別途フォローアップ項目として記録したか？
  • [ ] スクラム終了後、課題解決のための追加ミーティングが必要な関係者のみを招集したか？

チームメンバー個別共有チェックリスト ​

  • [ ] 昨日自分が完了した作業は何か？
  • [ ] 今日自分が行う作業は何か？
  • [ ] 進行を妨げている障害はあるか？

共有は 短く明確に（1〜2文程度） 行います。 問題解決の議論は、スクラム終了後に別途実施します。

チーム全体のスクラムボード例（ホワイトボード / オンライン協業ツール） ​

氏名昨日やったこと今日やること障害（Blocking Issue）

花子会員登録機能のテストケース作成および一部実行会員登録機能の全体テストおよびバグ報告テストサーバーが頻繁に切断される
健太ダッシュボード UI 作業チャートライブラリの適用および API 連携最新版の API 仕様書が未共有

このように運用することで、チームメンバーは毎日 チェックリストに沿って発言するだけ で済み、スクラムマスターは テーブルを更新するだけ で記録と共有を同時に完結できます。

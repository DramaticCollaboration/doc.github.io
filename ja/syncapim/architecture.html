SyncAPIM 4-JVMシステムアーキテクチャおよびデータベース設計 ​

SyncAPIMは、Java 25 (Virtual Threads)、Spring Boot 4.0、AgentScope Java (io.agentscope:agentscope-harness)、PostgreSQL 18.6 (JSONB + pg_trgm)、Redis 7 Stream、およびVue 3 + Vben Admin (@empasy/sync-apim-admin)の標準技術スタック上に構築された高性能API監視・セキュリティエージェントプラットフォームです。

1. パフォーマンス分離型4-JVMプロセスアーキテクチャ ​

大規模APIトラフィック環境において、パケット収集（I/O集約型）と正規表現・JWT脅威検知（CPU集約型）の負荷が管理コンソールやインラインゲートウェイの応答遅延に影響を与えないよう、4つの独立したJVMプロセスに分離して起動します。

1.1 JVM別役割およびポート規格 ​

2. マルチモジュールディレクトリおよびMaven座標構造 ​

sync-apim/Server/配下のすべてのモジュールは、全社標準に従いartifactIdと物理ディレクトリ名が1:1で一致しています。

  • 最上位親POM: com.empasy.sync.apim:sync-apim-parent:1.0.0-SNAPSHOT (sync-apim/pom.xml)
  • バックエンド親POM: com.empasy.sync.apim:sync-apim-server-parent:1.0.0-SNAPSHOT (sync-apim/Server/pom.xml)
  • 共通およびコアモジュール:
    • Server/sync-apim-common: 17のドメインエンティティ（WapfApiEndPoint、WapfDetectEvent等）、MyBatis-Plus Mapper、共通Service（WapfOpenApiSpecServiceImplドリフト監査エンジンを含む）
    • Server/sync-apim-base-core: MybatisPlusConfig、RedisConfig、AuthInterceptor、GlobalExceptionHandler
    • Server/sync-apim-module-system: システム認証・認可およびDB動的メニュー供給（/api/v1/apim/sys/permission/getUserPermissionByToken）

3. PostgreSQL 18.6ドメインデータベース設計 (db/02_schema_domain.sql) ​

従来のPostgreSQL 18.6 / PostgreSQL 18.6 + OpenSearchの二重ストレージを単一のPostgreSQL 18.6（sync_apimデータベース）に統合することで、運用の複雑さとメモリ占有率を低減しました。

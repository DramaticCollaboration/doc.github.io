SyncVerse & SyncAPIMセキュリティパック連携プロトコル ​

SyncWatchは、8大グローバル脅威フィード（OSV.dev、GitHub GHSA、NVD CVE、CISA KEV、Nuclei、OWASP CRS、MITRE ATT&CK、KISA）および診断ドキュメントからコンパイル・サンドボックス検証が完了したセキュリティルールを、VerseAuditPack（コード・依存関係・ペネトレーションテスト点検用）とApimDefensePack（ランタイムゲートウェイ防御用）の標準ペイロードとしてパッケージ化し、SyncVerseおよびSyncAPIMへリアルタイム配信します。

1. VerseAuditPack連携仕様（SyncWatch → SyncVerse） ​

SyncVerseは、受信したVerseAuditPackを使用して管理下の全社Gitリポジトリに対し、SCA（依存関係監査）、SAST（静的コード監査）、DAST（動的ペネトレーションテストプローブ）の3チャネルによるセキュリティ診断を実行します。

1.1 受信エンドポイントおよびMCPツール ​

  • SyncVerse受信REST API: POST /api/v1/verse/quality/security/audit-pack
  • SyncWatch送信REST API: POST /api/v1/watch/dispatches/broadcast (targetSystem: "SYNC_VERSE")

2. ApimDefensePack連携仕様（SyncWatch → SyncAPIM） ​

SyncAPIMは、受信したApimDefensePackをインメモリホットスワップレジストリに即座にロードし、SqlXssLexicalTokenizer（構文トークン指紋分析器）およびSandboxedDefenseEvaluator（Restricted SpELベースのピンセット仮想パッチ評価器）を通じて、アプリケーションを再起動することなくゼロデイ攻撃をリアルタイムで遮断します。

2.1 受信エンドポイントおよびMCPツール ​

  • SyncAPIM受信REST API: POST /api/v1/apim/waf/defense-pack/apply
  • SyncAPIM受信MCPツール: apim_receive_watch_defense_pack
  • SyncWatch送信REST API: POST /api/v1/watch/dispatches/broadcast (targetSystem: "SYNC_APIM")

2.2 ApimDefensePack JSONペイロード例 ​

json
{
  "packId": "adp-20261118-001",

  "externalId": "CVE-2026-41892",

3. 構文トークン指紋分析器（SqlXssLexicalTokenizer）とピンセット仮想パッチの結合原理 ​

SyncAPIMは、従来の浮動小数点ハッシュ／疑似ベクトル方式の代わりに、決定論的字句トークン分析器であるSqlXssLexicalTokenizerとSandboxedDefenseEvaluatorを組み合わせて動作します。

  1. 多層デコード（3-Round Multi-Layer Decoding）:
    • 攻撃者が検知回避のために適用した二重・三重URLエンコーディング（%2527）、HTMLエンティティ（&#x3c;）、Unicodeエスケープ（\u003c）、SQLインラインコメント（/*!50000UNION*/）を最大3ラウンドまで反復的に正規化します。
  2. 構文トークン指紋抽出（SqlXssLexicalTokenizer）:
    • 入力文字列を字句トークン（s 文字列、1 数値、& 論理演算子、U UNION、E SELECT、; 構文終端、k 危険キーワード、f(n) 関数呼び出し、x_script スクリプトタグ、x_event_handler イベントハンドラーなど）へ変換し、0.05ms以内に構造的攻撃指紋（grammarFingerprint）を生成します。
  3. ピンセット仮想パッチ（SandboxedDefenseEvaluator）:
    • SyncWatchが配信したApimDefensePackのターゲットパス（target_path）、HTTPメソッド（target_method）、検査位置（target_locations）が一致した場合にのみ、隔離されたSimpleEvaluationContext（型参照・リフレクション・ランタイムコマンド実行を事前遮断）上で防御表現式を評価します。
  4. カーネルeBPFリアルタイム遮断:
    • 脅威と判定されたパケットはL7ゲートウェイで即座に403 Forbiddenとして遮断されると同時に、反復攻撃元のIPはカーネルeBPF（XDP/TC）ブラックリストマップに登録され、ネットワークインターフェースレベルで超低遅延ドロップされます。

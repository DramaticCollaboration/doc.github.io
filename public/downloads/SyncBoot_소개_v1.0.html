[Slide 02] 02 · SyncBoot 란 (무 엇 을 하 는 프 로 그 램 인 가) ​

도메인 데이터의 안전한 자율 운영과 로우코드 개발 생산성을 극대화합니다. ​

엔터프라이즈 백엔드 시스템을 새로 구축할 때도 쓰고, 이미 운영 중인 대규모 데이터베이스를 관리할 때도 씁니다. 도메인 자율 운영과 스키마 거버넌스를 중심으로 설명합니다.

한 문장으로 요약: 시스템 도메인 맥락을 인지하여 안전한 CRUD 운영, 지능형 스키마 설계, RBAC 보안 통제 및 고성능 배치를 자율 수행하는 AI 백엔드 프레임워크

  • 안전한 DDL 승인 체계: DB 스키마 변경 시 개발자 사전 승인(HITL) 필수 보장
  • 정밀한 데이터 격리: Multi-Tenant 완벽 분리 및 컬럼 단위 세분화 RBAC 통제
  • 소스코드 무결성 보존: 운영 CRUD와 소스코드 수정을 엄격히 분리하여 안전성 확보

주요 기능 4대 축:

  1. 도메인 CRUD 자율 운영 및 쿼리 실행: 구축된 시스템의 비즈니스 도메인을 인지하여 안전한 데이터 조작과 트랜잭션을 자율 처리합니다.
  2. 지능형 스키마 설계 및 DDL 제안: 자연어 요구사항을 분석하여 정규화된 3-File 표준 DDL을 설계하고 개발자에게 승인을 요청합니다.
  3. 로우코드 API & 서비스 템플릿 생성: Entity 정의만으로 Controller, Service, Mapper, Vue UI 코드를 원클릭으로 자동 생성합니다.
  4. 멀티테넌트 및 세분화 IAM 보안 관리: 테넌트별 데이터베이스 격리, 데이터 마스킹, 권한 감사 로그를 엔터프라이즈 레벨로 통제합니다.

[Slide 03] 03 · 전 체 구 조 (한 눈 에 보 기) ​

서비스 개발 요청이 오기 전에, 도메인 스키마와 보안 정책을 미리 정립합니다. ​

SyncBoot의 워크플로우는 세 가지 단계로 나뉩니다. 도메인을 모델링하고 3-File 스키마를 설계하며(A), 로우코드 엔진과 AI 에이전트로 서비스를 고속 실행하고(B), 분산 로그 모니터링 및 감사 이력으로 시스템을 안정화합니다(C).

단계구분주요 내용
PRE-PROCESSA. 도메인 모델링 및 스키마 설계자연어 기반 도메인 엔티티 분석 — 비즈니스 명세를 ERD 및 테이블 구조로 변환
PRE-PROCESSA. 도메인 모델링 및 스키마 설계3-File DB 스키마 표준 수립 — init.sql / 도메인.sql / sample.sql 자동 분리
PRE-PROCESSA. 도메인 모델링 및 스키마 설계테넌트 격리 및 인덱스 정책 수립 — 대용량 트래픽 대비 파티셔닝 및 인덱스 최적화
CORE EXECUTIONB. 로우코드 실행 및 IAM 통제1. 다섯 에이전트 협업 실행 — 운영-스키마-보안-MCP-배치가 유기적으로 결합
CORE EXECUTIONB. 로우코드 실행 및 IAM 통제2. 로우코드 풀스택 자동 빌드 — Spring Boot + Vue3 표준 보일러플레이트 고속 생성
CORE EXECUTIONB. 로우코드 실행 및 IAM 통제3. 세분화 RBAC 및 데이터 마스킹 — JWT 토큰 및 역할별 데이터 접근 권한 실시간 감시
POST-PROCESSC. 분산 로깅 및 감사 추적클러스터 분산 로그 자율 수집 — 장애 시 에이전트가 서버 로그를 직접 추출하여 전달
POST-PROCESSC. 분산 로깅 및 감사 추적대용량 배치 및 스케줄러 모니터링 — Quartz/Spring Batch 작업 상태 실시간 추적
POST-PROCESSC. 분산 로깅 및 감사 추적데이터 리니지 & 변경 감사 이력 — 누가 언제 어떤 데이터를 수정했는지 완벽 보존

[Slide 04] 04 · 핵 심 에 이 전 트 (A G E N T S) ​

에이전트 다섯이 엔터프라이즈 백엔드를 자율 운영합니다. ​

요청 한 건이 들어오면 각자 맡은 역할을 수행하고 결과를 반환합니다. 런타임 운영과 개발 승인이 엄격히 통제됩니다.

  • 01 Domain Operator Agent (도메인 CRUD 자율 운영) (AI 사용 · 자동 수행): 자신이 상주하는 시스템 도메인을 인지하여 안전한 데이터 CRUD 및 비즈니스 쿼리를 실행합니다.
  • 02 Schema Architect Agent (지능형 DDL & 스키마 설계) (AI 사용 · 확인 1회): 새로운 데이터 구조 요구 시 정규화된 테이블 DDL을 제안하고 개발자에게 승인을 요청합니다.
  • 03 Security IAM Agent (RBAC 권한 & 테넌트 격리) (AI 사용 · 자동 수행): 사용자 역할별 메뉴/API 접근 제어, 민감정보 마스킹 및 멀티테넌트 침범을 실시간 감시합니다.
  • 04 MCP Dispatcher Agent (표준 MCP 서비스 연동) (AI 사용 · 자동 수행): SyncVerse 및 타 에이전트와 A2A 통신을 위한 표준 Tool(스키마 조회, 로그 수집 등)을 제공합니다.
  • 05 Batch Orchestrator Agent (고성능 배치 & 스케줄러) (AI 사용 · 확인 1회): 대용량 데이터 집계 및 주기적 Quartz 배치 작업을 최적의 시간에 분산 스케줄링합니다.

[확장성] 고객의 특화 비즈니스(예: 금융 정산, 물류 트래킹, 결제 게이트웨이 등)에 맞춤형 백엔드 워커 에이전트를 손쉽게 추가하여 무한히 확장할 수 있습니다.

[Slide 05] 05 · 유 지 보 수 현 장 (무 엇 이 힘 든 가) ​

단순 CRUD 코딩과 DB 스키마 관리에 개발 리소스가 낭비됩니다. ​

엔터프라이즈 백엔드는 단순 반복 작업이 많고, 스키마 변경 사고나 권한 누락 시 치명적인 비즈니스 장애로 이어집니다.

  1. 단순 반복 CRUD API 개발에 백엔드 리소스 40% 소모: 매 프로젝트마다 동일한 컨트롤러, 서비스, DTO, 매퍼 코딩을 반복하며 고급 개발 리소스 낭비
  2. DB 스키마 변경 시 영향도 파악 및 마이그레이션 사고: 컬럼 하나 추가/수정 시 기존 쿼리와 연관 API 영향도를 파악하지 못해 런타임 에러 발생
  3. 멀티테넌트 및 세분화 RBAC 권한 구현의 높은 난이도: 고객사별 데이터 분리 및 역할별 세부 권한 로직을 처음부터 구현하느라 수개월 소요
  4. 대용량 배치 작업 실패 시 원인 파악 및 수작업 재처리 난항: 야간 배치 장애 발생 시 수백만 건의 데이터 중 어느 지점에서 실패했는지 추적이 어려움
  5. 장애 발생 시 분산 클러스터 서버 로그 수집 지연: 서버가 수십 대로 분산된 환경에서 특정 트랜잭션의 로그를 모으는 데 많은 시간 소요

[Slide 06] 06 · 역 할 분 담 (A I vs 사 람) ​

AI는 스키마 설계와 CRUD 운영을 맡습니다. DDL 승인은 개발자가 합니다. ​

AI에게 '주문 정산 도메인 스키마를 설계하고 데이터를 운영해라'라고 하면 잘합니다. 실제 프로덕션 DB 구조 변경은 엔지니어가 승인합니다.

01 SCHEMA / CODE GEN (스키마 모델링 및 보일러플레이트 자동화)02 HUMAN IN THE LOOP (백엔드 아키텍트 (사람))03 DOMAIN OPERATOR / IAM (안전한 데이터 런타임 운영 및 보안)
3-File 표준 DDL 및 인덱스 구조 자동 생성AI가 제안한 DDL 및 스키마 변경안 최종 승인권한 검증된 트랜잭션 CRUD 자율 실행
Spring Boot + Vue3 풀스택 코드 생성멀티테넌트 격리 정책 및 보안 규칙 확정클러스터 서버 로그 직접 수집 및 자가진단
도메인 비즈니스 규칙 및 검증 로직 수립가장 핵심적인 안전 검증 지점배치 스케줄링 및 데이터 리니지 감사 기록

핵심 요약: SyncBoot를 쓰면: 개발자가 매번 지루한 CRUD 코딩과 위험한 DB 마이그레이션에 시간을 뺏기지 않고, AI가 제안한 정규화 DDL을 '승인'하기만 하면 견고한 엔터프라이즈 백엔드가 즉시 가동됩니다.

[Slide 07] 07 · 화 면 1 · 도메인 통합 관제 (샘플 화면) ​

백엔드 시스템 전반의 상태와 도메인 데이터를 한눈에 관제합니다. ​

엔터프라이즈 서버 인스턴스, DB 커넥션 풀, Redis 캐시 및 도메인 트랜잭션을 실시간 모니터링합니다.

이 화면에서 할 수 있는 일 (6대 기능):

  1. 도메인 엔티티 헬스체크: 등록된 도메인 테이블별 레코드 수, 트랜잭션 TPS 및 지연시간 실시간 표시
  2. JVM & 리소스 메트릭 모니터링: 힙 메모리 사용량, CPU 로드, GC 발생 횟수 및 HikariCP 풀 상태 감시
  3. 활성 트랜잭션 추적: 현재 실행 중인 롱러닝 쿼리 및 락(Lock) 경합 상태를 실시간 감지
  4. 에이전트 런타임 상태 확인: SyncBoot 내 상주하는 5개 에이전트의 구동 상태 및 메모리 확인
  5. Redis 캐시 히트율 분석: 도메인 쿼리 캐시 히트율 및 TTL 만료 정책 실시간 시각화
  6. 비상 정지 및 서킷 브레이커: 트래픽 폭증 시 특정 도메인 API를 안전하게 차단하는 서킷 브레이커 제어

[Slide 08] 08 · 화 면 2 · 지능형 스키마 스튜디오 (샘플 화면) ​

자연어 요구사항을 입력하면 3-File 표준 DDL이 완성됩니다. ​

초보자도 알기 쉬운 ERD 시각화와 함께 3-File(init.sql, 도메인.sql, sample.sql) 스크립트를 자동 생성합니다.

이 화면에서 할 수 있는 일 (6대 기능):

  1. 자연어 기반 테이블 설계: '정기 결제 구독 테이블 만들어줘' 입력 시 DDL 자동 생성
  2. 3-File SQL 구조 자동 분리: 플랫폼 기본(init), 도메인 특화(domain), 개발용 샘플(sample)로 분할
  3. 대화형 ERD 비주얼 뷰어: 테이블 간 PK/FK 관계와 인덱스 구조를 다이어그램으로 시각화
  4. 스키마 변경 영향도 분석: 컬럼 삭제/수정 시 영향을 받는 쿼리와 서비스 목록 사전 탐색
  5. 마이그레이션 DDL 승인 콘솔: 개발자가 검토 후 원클릭 승인 시 실제 DB에 안전하게 DDL 반영
  6. 멀티 DB 방언(Dialect) 지원: MySQL, PostgreSQL, Oracle, MariaDB 문법 자동 변환

[Slide 09] 09 · 화 면 3 · 로우코드 API 생성기 (샘플 화면) ​

  5. 행 단위(Row-Level) 데이터 보안: 자신이 속한 지점이나 팀의 데이터만 조회되도록 SQL 자동 주입

Spring Batch와 Quartz 기반의 대규모 데이터 처리 작업을 시간표로 관리하고 실행 상태를 실시간 추적합니다.

  3. 실패 스텝 자동 재시도 및 Skip: 네트워크 지연 시 지수 백오프(Exponential Backoff) 재시도 자동 수행
  4. 배치 파라미터 동적 주입: 실행 시점의 날짜 변수 및 런타임 파라미터를 유연하게 전달
  5. 배치 실행 이력 및 락 관리: 과거 실행 성공/실패 통계와 중복 실행 방지 분산 락(Redis Lock) 제어
  6. 장애 발생 시 관리자 긴급 알림: 배치 실패 시 스택트레이스를 분석하여 담당자 Slack/Email 즉시 통보

이 화면에서 할 수 있는 일 (6대 기능):

  1. 에이전트 직접 질의 로그 수집: 중앙 저장소 장애 시에도 에이전트가 서버 로컬 로그를 즉시 추출
  2. Trace ID 기반 분산 트랜잭션 추적: 클라이언트 요청부터 DB 쿼리까지 이어지는 전체 콜체인 시각화
  3. AI 자연어 에러 원인 분석: 복잡한 Java NullPointerException의 원인을 한글로 명확히 해설
  4. Elasticsearch / OpenSearch 연동: 대규모 로그 검색을 위한 중앙 검색 엔진 옵션 완벽 지원
  5. 실시간 로그 스트리밍 (Tail): 서버 터미널 접속 없이 웹 콘솔에서 실시간 로그 흐름 모니터링
  6. 민감 로그 자동 마스킹: 로그 파일에 기록되는 비밀번호, 토큰 등 개인정보 자동 필터링

[Slide 13] 13 · 화 면 7 · 데이터 리니지 & 감사 이력 (샘플 화면) ​

이 화면에서 할 수 있는 일 (6대 기능):

  1. Before/After 데이터 Diff 뷰: 테이블 레코드 수정 전과 후의 변경된 컬럼값을 색상으로 대조
  2. 작업자 & 클라이언트 IP 추적: 누가, 어느 PC에서, 어떤 권한으로 조작했는지 감사 로그 보존

  4. 도메인 데이터 리니지 맵: 데이터가 어느 배치나 서비스 API를 거쳐 흘러갔는지 계보 시각화
  5. 위변조 방지 해시 체인: 감사 로그의 임의 삭제나 수정을 방지하는 블록체인형 해시 검증

[Slide 14] 14 · 담 당 자 가 하 는 일 (에 이 전 트 와 사 람) ​

개발자가 하는 일은 제안된 스키마를 '승인'하는 것입니다. ​

도메인을 분석하고, DDL을 설계하며, CRUD를 실행하고 로그를 수집하는 일은 AI 에이전트가 합니다. 개발자는 제안된 스키마 구조가 맞는지만 봐 주시면 됩니다.

  1. STEP 01 (SCHEMA / CODE GEN): 3-File DDL 및 서비스 템플릿 설계 — 자연어 요구사항을 바탕으로 정규화된 테이블 DDL, 인덱스 정책, 로우코드 서비스 코드를 준비해 내놓습니다.
  2. STEP 02 (주요 역할) (백엔드 엔지니어 (사람)): DDL과 보안 정책을 승인합니다 — 제안된 DB 스키마 구조와 테넌트 격리 규칙을 검토하고 실제 반영을 승인합니다. 요청 한 건에 한 번 검토합니다.
  3. STEP 03 (DOMAIN OPERATOR / IAM / BATCH): 안전하게 운영하고 감사 로그를 남김 — 승인된 스키마 위에서 비즈니스 CRUD를 자율 운영하고, 배치 작업을 스케줄링하며, 모든 이력을 기록합니다.
  • 정교한 스키마 거버넌스: DB 변경 사고가 발생하지 않습니다 (모든 DDL 변경이 3-File 표준 규칙과 개발자 승인 절차를 거치기 때문입니다.)
  • 투명한 책임 추적: 누가 어떤 데이터를 바꿨는지 남습니다 (데이터 조작자와 AI 에이전트의 실행 로그가 타임스탬프와 함께 완벽히 기록됩니다.)

[Slide 17] 17 · 다 른 점 (기 존 도 구 와 의 차 이) ​

단순한 코드 생성기나 ORM 도구와는 차원이 다릅니다. ​

코드만 몇 줄 만들어주는 도구가 아니라, 도메인 맥락을 인지하여 런타임 데이터 운영과 보안, 스키마 거버넌스까지 책임지는 백엔드 플랫폼입니다.

  1. 시스템 도메인 컨텍스트를 스스로 인지합니다: 자신이 동작 중인 구체적인 서비스의 비즈니스 목적을 이해하고 안전한 범위 내에서만 CRUD를 수행합니다.
  2. 안전한 3-File DB 스키마 표준을 강제합니다: init/domain/sample 3-File 구조와 개발자 승인 절차를 통해 스키마 무결성을 보장합니다.
  3. 표준 MCP 도구를 탑재하여 A2A 통신을 완벽 지원합니다: SyncVerse 및 타 에이전트와 Model Context Protocol로 연결되어 자가치유 파이프라인에 참여합니다.
  4. 분산 클러스터 서버 로그를 자율 수집합니다: 중앙 로깅 인프라가 다운되어도 에이전트가 로컬 서버 로그를 직접 추출하여 전달합니다.
  5. 운영 데이터와 소스코드 수정을 엄격히 분리합니다: 런타임 에이전트는 소스를 건드리지 않고, 코드 수정은 SyncVerse의 SDK 코딩 에이전트에 위임합니다.

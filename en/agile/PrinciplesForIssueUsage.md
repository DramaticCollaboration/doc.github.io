## Core Principles for Effective Issue Usage

### 1. **Assignment Principles**

- **Assign to the current owner**: An issue must always be assigned to the person currently performing the actual work.
- **Acknowledge assignments promptly**: Once an issue is assigned, the assignee should immediately acknowledge it and indicate whether work has started.
- **No unassigned issues**: Issues without an assigned owner are easily overlooked and neglected.

### 2. **Commenting Principles**

- **Comment upon completion**: Always add a comment summarizing the resolution when work is completed.
- **Share progress updates**: Post interim progress comments along the way, especially for long-running tasks.
- **Comment on status transitions**: When changing an issue's status (e.g., In Progress → Done), explicitly state the reason for the transition.
- **Avoid meaningless comments**: Do not repeatedly post low-value remarks such as "Acknowledged" or "Working on it."

### 3. **Status Management Principles**

- **Update status in real time**: Update the issue status immediately to reflect current progress.
- **Define statuses clearly**: Establish clear, team-wide definitions for each status and apply them consistently.
- **No stale statuses**: Do not leave issues sitting in "In Progress" for extended periods without activity.

### 4. **Issue Authoring Principles**

- **Clear titles**: Write titles that convey what needs to be done at a glance.
- **Detailed descriptions**: Include comprehensive details such as reproduction steps, expected results, and actual results.
- **Complete required fields**: Always fill in mandatory fields such as priority, time estimate, and component.
- **Avoid vague language**: Do not use ambiguous phrases like "There's a bug" or "Please fix this."

### 5. **Workflow Compliance Principles**

- **Follow the defined workflow**: Strictly adhere to the workflow established by the team.
- **Follow the review process**: Never skip required steps such as code reviews or QA verification.
- **Maintain process consistency**: Ensure every team member follows the same process.

## Example: Ideal Issue Processing Flow

1. **Issue Created** → Assign an owner + set priority
2. **Work Started** → Change status to "In Progress" + post start comment
3. **In Progress** → Post interim progress comments (as needed)
4. **Work Completed** → Change status to "Done" + **post a detailed resolution comment**
5. **Review Required** → Change status to "In Review" + assign a reviewer

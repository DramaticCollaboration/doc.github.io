Engineering Work Logs and Post-Mortems (Logs) ​

This section is a practical engineering log where the Empasy engineering team traces and resolves the root causes of technical incidents, memory leaks, concurrency bottlenecks, and build signing errors encountered in production environments and release build pipelines.

Beyond simple task lists, each entry is structured in a standardized post-mortem format: Reproduction Environment -> Root Cause Analysis (RCA) -> Fix Verification -> Recurrence Prevention.

Work Logs and Post-Mortems ​

1. SyncETA (Desktop App & QA Engine) ​

  • 2026-02-10: Electron Multi-Webview DOM Snapshot Memory Leak Analysis and Fix: Identifying the root cause of renderer process V8 heap exhaustion when recording 50+ consecutive scenarios and optimizing memory release.
  • 2026-02-18: Stabilizing Playwright Action Timeouts for Lazy-Loaded Components: Improving virtual scroll anchor wait mechanisms under infinite scroll and lazy-mount environments.
  • 2026-03-10: Building an Unattended Windows Authenticode Signing and Apple Notarization Pipeline: GitHub Actions runner-based EV certificate code signing and macOS Gatekeeper pass-through pipeline.
  • 2025-08-27: Desktop Debug Crash Analysis: Troubleshooting Linux inotify file watcher limit exceeded (ENOSPC: System limit for number of file watchers reached).
  • 2025-08-27: Electron Development Environment Debugging Log: Guide for connecting the IntelliJ Electron main process remote debugger (ws://127.0.0.1:5858) and configuring breakpoints.

2. SyncVerse & SyncBoot (Control Plane & MSA Backend) ​

  • 2026-02-25: Multi-Agent Transaction Synchronization Incident Recovery Based on Redis Redlock and SSE: Resolving distributed lock lease renewal failures and Saga rollback synchronization issues during network partitions.
  • 2026-03-02: Fixing MyBatis-Plus Async Thread Tenant ID Loss in Multi-Tenant Environments: Replacing ThreadLocal-based tenant context with ScopedValue to resolve missing propagation across virtual thread pools.

Engineering Post-Mortem Principles ​

  1. Blameless Post-Mortem: Focus on system architecture and process weaknesses to turn failures into organizational assets.
  2. Metric-Driven Timeline Recording: Explicitly record the timeline covering incident occurrence (T0), detection (T1), mitigation (T2), and full resolution (T3).
  3. Code-Level Diff Documentation: Include before/after source code diffs so subsequent engineers can reference fixes immediately.
